## [2.4.5] - 2026-09-29

> **Maintained by [JAP](https://whatsapp.com/channel/0029VbEVFrILtOjAOu4FXa3r).** `@japofc/baileys` is a fork of [WhiskeySockets/Baileys](https://github.com/WhiskeySockets/Baileys) — the upstream project that provides the core WhatsApp protocol — with a vendored QR-code generator by [Nayuki](https://github.com/nayuki/QR-Code-generator). On top of that base, JAP builds and maintains the fork's own layer: its features, tooling, and fixes. This release brings the fork to feature parity with Baileys 7.0. **732 tests green, `tsc` clean.**

### Added
- **Ten core WABinary node-reader helpers** 🆕 — the single most repeated chore in socket code is parsing WA's `{ tag, attrs, content }` stanza trees (IQ results, notifications, receipts): optional-chaining into `attrs`, coercing string attrs to int/bool, counting repeated children. These round out the reader surface in `lib/WABinary/generic-utils.js` (auto-exported through the top barrel), all pure, null-safe, and reusing the cached child index: `getBinaryNodeAttr` (own-attr read with fallback), `getBinaryNodeChildAttr` (attr of the first matching child), `getBinaryNodeChildInt` (int from attr/content — *absent* returns `undefined` so callers tell "missing" apart from "present but not a number", *unparseable* returns the fallback), `getBinaryNodeChildBool` (`true`/`1`/`yes`/`on`), `hasBinaryNodeChild`, `countBinaryNodeChildren`, `getBinaryNodeChildrenAttrs` (attrs of every match), `filterBinaryNodeChildren` (predicate filter, safe on non-array content), `getBinaryNodeContentString` (coerce a node's own Buffer/Uint8Array/string content to UTF-8), and `getBinaryNodeErrorStatus` (non-throwing counterpart of `assertNodeErrorFree` — returns `{ code, text }` or `undefined` so callers branch on failures instead of `try/catch`). Fully typed in `generic-utils.d.ts` and covered by `tests/v245-core-node-helpers.test.js` (9 cases).
- **Stateful poll manager (`createPollManager`)** 🆕 — the missing companion to `getAggregateVotesInPollMessage`. The low-level aggregator is stateless and double-counts a voter who changes their mind (WhatsApp re-sends the voter's *full* current selection on every change). This manager remembers a poll once you `register()` it, ingests decrypted votes as they arrive, and gives you live `tally()`, `winner()` (tie-aware), `getVoterChoice()`, `totalVoters()`, and a `render()` bar chart — each voter counted once with only their latest choice. Accepts option names, sha256 hex hashes, or the raw hash Buffers WA sends. New module `lib/Utils/poll-manager.js` with full `.d.ts`, exported from the Utils barrel, covered by `tests/poll-manager-and-helpers.test.js`.
- **Session-health monitor (`createSessionHealthMonitor`)** 🆕 — watches `messages.upsert` for bursts of undecryptable `CIPHERTEXT` messages (the signature of a dead Signal session / Bad-MAC drift), counts failures per contact inside a sliding window, and fires `onUnhealthy`/`onRecover` once a contact crosses/clears a threshold. Purely observational; never throws into the event loop. Ships with JID-canonicalization helpers `canonicalizeJid` (device-suffix normalization) and `makeJidCanonicalizer` (async LID↔PN unification) so a contact is always keyed by one identity across the PN/LID split. New module `lib/Utils/session-health.js` with full `.d.ts`, exported from the Utils barrel, covered by `tests/session-health.test.js` (9 cases).
- **LID ↔ PN mapping helpers on the socket** — `getLIDForPN`, `getPNForLID`, `getLIDsForPNs`, `getPNsForLIDs`, and `storeLIDPNMappings` are now returned directly from the socket (and typed in `chats.d.ts`), so callers can do `sock.getLIDForPN(pn)` without reaching into `signalRepository.lidMapping`. This matches the public surface popular forks expose. The logic already existed internally; this only exposes it. Covered by the smoke test.
- **Message de-duplication guard (`createMessageDedupe`)** 🆕 — a bounded LRU of message keys you've already handled, so a bot doesn't reply twice when WhatsApp re-delivers a message (reconnect, history sync, placeholder resend, retries). `seen(key)` checks-and-records in one call; also `has`/`add`/`delete`/`clear`/`size` and an optional `ttlMs`. New module `lib/Utils/message-dedupe.js` with full `.d.ts`, exported from the Utils barrel, covered by `tests/message-dedupe.test.js` (7 cases).
- **Ten new toolkit helpers** — `partition` / `zip` (array-tools), `formatCountdown` (time-tools), `wordCount` / `ellipsisMiddle` (text-extras), `jidType` (jid-extras), `randomString` (random-tools), `isNumeric` (validate-tools), `firstEmoji` (emoji-tools), and `maskJid` (mask-tools, for safe logging). ### Fixed
- **WAM encoder guards unknown attributes/events** — `lib/WAM/encode.js` looked up global-attribute and event names with an unchecked `.find(...)`, so a bad name would crash with a cryptic `cannot read properties of undefined (reading 'id')`. It now throws a clear, named error instead. (This encoder is currently dormant, so the fix is purely defensive.)
- **Randomized helpers now stay in bounds with an injected RNG that returns `1.0`** — `sample` (array-tools), and `randomInt` / `randomPick` / `shuffle` / `rollDice` / `randomString` (random-tools), and `randomEmoji` (emoji-tools) all computed an index as `Math.floor(random() * n)`. That's safe for `Math.random()` (range `[0, 1)`), but the toolkit explicitly documents an **injectable** `random` for deterministic/provably-fair use — and the library's own `hash01()` returns `[0, 1]` **inclusive**. When such an RNG yields exactly `1.0`, the index landed one past the end: `sample`/`randomPick`/`randomEmoji` returned `undefined` (and `sample` silently dropped a real element), `randomInt` returned `max + 1` (violating its documented inclusive range), `shuffle` swapped in an `undefined`, and `rollDice` rolled `sides + 1`. Each site now clamps to the last valid index. Covered by `tests/v245-upgrades-and-rng-clamp.test.js`.
- **`hasEmoji` is stateless** — the new emoji-presence check deliberately reuses `extractEmojis(...)` rather than calling `.test()` on the module-level `/…/gu` regex, which would advance `lastIndex` and flip its result between calls. (An audit confirmed no other `.test()` in the codebase runs against a global-flag regex.)
- **Work cooldown survives a restart** — `createEconomy().load()` rebuilt each account from a fixed field list and silently dropped `lastWorkAt`, so a save + reload reset the `work()` cooldown and let users earn again immediately. `load()` now restores `lastWorkAt` too. Covered by `tests/v245-round2-helpers-and-persistence.test.js`.
- **Reputation anti-farm cooldown survives a restart** — `createReputation()` promises *"per-giver cooldowns so nobody farms it"*, but `toJSON()`/`load()` only persisted user tallies, not the `cooldowns` map — so a reload wiped every cooldown and re-opened rep farming. The cooldown map is now serialized and restored. Covered by the same test file.
- **Version metadata was out of sync** — `package.json`, the README banners, and the release test disagreed (`2.4.4` vs `2.5.0`). Everything is now pinned to `2.4.5`.

- **Everyday text/broadcast helpers (`lib/Utils/text-tools.js`)** — `parseMentions(text)` (extract `@62812…` mentions into ready-to-use jids, de-duplicated), `extractGroupInviteCode(link)` (any chat.whatsapp.com URL shape), `sock.joinGroupViaLink(linkOrCode)`, and `sock.sendBroadcast(jids, content, { delayMs, onProgress })` — paced multi-jid sending with per-jid outcomes that never dies mid-run. All pure logic is dependency-free; 16 dedicated unit tests.
- **`sendStatusMention(content, mentions, options?)`** — post a status and notify specific users or whole groups with the "mentioned you in their status" bubble (upstream 7.0.0-rc10 parity). Works with any status content type; fan-out pacing via `{ delayMs }`. The underlying status-mention wire path (protocolMessage type 25 + `is_status_mention` meta node) already existed; this adds the named, validated, typed API on the socket.

### Fixed
- **Windows Desktop pairing was broken** — since ~2026-06-30 WhatsApp rejects handshakes advertising the retired `WIN32` web sub-platform: the socket closed with 428 within ~600ms, before any QR was emitted, making `Browsers.windows('Desktop')` unusable. Now advertises `WIN_HYBRID` (the modern native Desktop identity). This matters because a Desktop sub-platform is the only way to request **full** history sync.
- **Profile picture tctoken was sent in the wrong place** — the privacy token must be nested INSIDE the `<picture>` node; as a sibling the server ignores it, so privacy-gated profile pictures came back empty even with a valid token. Also now sends the token issue time as the `t` attr and refuses to advertise timestamp-less tokens.
- **`sendMusic()` no longer silently drops unknown `embeddedMusic` fields** — protobufjs discards unrecognized keys at encode time, so a typo'd or unsupported field (e.g. `durationSeconds`) simply vanished from the wire with zero feedback. Unknown fields now throw a clear 400 listing every supported field name; every supported field is covered by a real wire round-trip test.
- **Username APIs: actionable error + runtime override for rotated query IDs** — WhatsApp rotates the GraphQL query_ids behind `checkUsername`/`setUsername`/etc. server-side; a rotated id failed with an opaque `GraphQL server error: Bad Request`. Bad Request failures now explain the rotation and how to fix it, and a new `usernameQueryIds` socket-config option hot-patches any rotated id without waiting for a package update.
- **CLI no longer executes on import** — `lib/cli.js` printed help output as a side effect when imported (e.g. by a bundler or module walker). The runner now only executes when the file is the actual process entry point; `node lib/cli.js` and the `japofc-baileys` bin shim both still work (verified against a real tarball install).

### Changed

It stays log-friendly: full banner on an interactive terminal, a single plain-text line (zero ANSI codes) in CI/pm2/piped output so structured log pipelines are never corrupted. `NO_COLOR=1` strips styling only (per the no-color.org spec — it is a color opt-out, not a banner opt-out).

## [2.3.0] - 2026-09-12

### Added
- **Central ffmpeg resolver with auto-detection** (`lib/Utils/ffmpeg-path.js`) — every ffmpeg consumer (video thumbnails in `extractVideoThumb`, sticker/voice-note conversion in `MediaManager` and the message builders, VoIP `AudioFeeder`) now resolves the binary through one resolver: explicit `setFfmpegPath()` / `FFMPEG_PATH` env var → `ffmpeg-static` (if installed) → `@ffmpeg-installer/ffmpeg` (if installed) → system `PATH`. `ffmpeg-static` and `@ffmpeg-installer/ffmpeg` are now **optional** peer dependencies: `npm i ffmpeg-static` is all you need on desktop/server platforms — zero config, nothing bundled by default (package size unchanged). When nothing is found, features fail with a per-platform install hint (Termux-aware: `pkg install ffmpeg`) instead of `spawn ffmpeg ENOENT`. New exports: `setFfmpegPath`, `resolveFfmpegPath`, `requireFfmpegPath`, `ffmpegInstallHint`; new suite `tests/ffmpeg-path.test.js`. Verified end-to-end: voice-note conversion produces valid Ogg/Opus using the auto-detected `ffmpeg-static` binary on a machine with no system ffmpeg.
- **`createDebugMonitor(sock)`** — structured, safe observability snapshots via `getDebugInfo()`: connection state + last disconnect reason, socket uptime, message latency percentiles (p50/p90/p99), send-retry statistics, Signal error tallies (noSession/badMac/missingKeys/preKeyErrors), VoIP + WASM state, and process memory. Privacy is enforced, not promised: QR payloads are counted but never stored, and the entire snapshot passes through `redactSecrets()` before returning — QR, pairing codes, auth keys, tokens and private keys can never appear in it. Fully typed (`DebugInfo`, `DebugMonitor`).
- **Message regression test suite** (`tests/message-regression.test.js`) — the protocol-drift-prone shapes, each through a real protobuf encode→decode round-trip: buttons, native flows (quick_reply/single_select), carousel cards (media headers + invalid-header rejection), poll/quiz (V3/base/V5 routing + messageSecret), event, location/contact (vcard byte-identical), reaction (add+remove), edit/delete protocolMessages, quoted messages (incl. cross-type), ephemeral contextInfo.expiration and disappearing-mode EPHEMERAL_SETTING.
- **Store consistency, reconnect lifecycle, Signal recovery and debug-info test suites** (`tests/store-consistency.test.js`, `tests/reconnect-lifecycle.test.js`, `tests/signal-recovery.test.js`, `tests/debug-info.test.js`).

### Fixed
- **In-memory store consistency** — every event handler resolved the message bucket with a different jid (raw vs `remoteJidAlt` vs normalized), so receipts, reactions, deletes and status updates could silently miss messages stored under device-suffixed or LID-alt keys (all reproduced). One canonical resolver is now used everywhere. Also fixed: `contacts.update` aborting the whole batch on the first unknown contact **and** never actually merging update fields (self-assign no-op); `bind()` called twice duplicating every listener; missing `groups.upsert` binding leaving `groupMetadata` empty for event-driven consumers.
- **Reconnect lifecycle hardening** — `autoReconnect`: a server answering `restartRequired` on every connect caused a tight spin loop (repro: 165 sockets in 200ms) — only the *first* consecutive `restartRequired` reconnects immediately now, repeats back off; a throwing socket factory (e.g. `makeWASocketAuto` version fetch while offline) permanently killed the chain — now retried with backoff under `maxAttempts`; `start()` called twice ran two parallel reconnect chains — now idempotent; replaced sockets are `end()`ed so no half-open ws lingers; `loggedOut`/`timedOut`/network-loss behaviour regression-locked.
- **Signal session recovery** — the Signal error code carried by retry receipts (`<error code="7"/>`) was parsed nowhere (`parseRetryErrorCode`/`isMacError` were dead code): peers reporting Bad MAC / InvalidMessage (session provably out of sync) waited for `retryCount > 1` **plus** an hour-long throttle before the session was rebuilt. MAC errors now force immediate session recreation, even on the first retry.
- **Single-contact messages dropped `displayName`** — `sendMessage(jid, { contacts: { displayName, contacts: [{ vcard }] } })` sent a nameless `ContactMessage` when there was exactly one contact (the outer `displayName` was ignored).

- **auto-reconnect race condition** — a socket emitting `close` twice scheduled two parallel reconnect chains, and a late `close`/`open` from an already-replaced socket spawned ghost sockets / corrupted the backoff counter. Handlers now ignore stale sockets and de-duplicate `close` per socket. Regression-locked in `tests/reconnect-stress.test.js`.
- **VoIP call recovery** — the media watchdog retried rekey+offer forever on a dead relay with no signal to the caller. Recovery now has a bounded per-call budget (`watchdogMaxRecoveries`, default 3): `call-degraded` events carry `{ attempt, maxRecoveries }`, exhausting the budget emits `call-unrecoverable` and force-ends the call (reason `"unrecoverable"`) so upper layers can redial; a healthy relay resets the budget. `recoverCall()` now throws when no engine is connected instead of silently reporting a fake success.

### Changed
- **README limitations updated (no false claims)** — "Group message history sharing": WhatsApp shipped the official feature (last 25–100 messages, E2EE) in Feb 2026, but its wire format still has no public capture (re-verified Sep 2026); `shareGroupHistory()` is explicitly documented as a DM-forwarding *workaround*, not the native flow. "Music messages": documented as experimental with unverified official-client interop — `sendMusic()` emits a correct proto but real catalog IDs/artwork flow have no public capture.

- **WhatsApp integration test suite** (`tests/integration.test.js`) — pairing-code flow (random Crockford + custom 8-char codes), binary-node wire codec round-trips, message pipeline → protobuf wire, multi-file auth-state persistence, connection lifecycle.
